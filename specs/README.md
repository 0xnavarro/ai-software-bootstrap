# Specifications

A specification describes **what the system must do**, not how the repository will implement it.

Active specs live in `specs/active/`.

A good spec contains:

- problem and context;
- actors;
- use cases;
- functional requirements;
- non-functional requirements;
- invariants;
- acceptance criteria;
- out-of-scope items;
- open questions.

The implementation plan is created only after the spec is reviewed.
